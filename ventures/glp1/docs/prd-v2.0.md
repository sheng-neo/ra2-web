# GLP-1 中文 AI 伴侣 · PRD v2.0（暂名「稳瘦」）

日期：2026-11-19 · 状态：等你确认第 0 节的 5 个决定后开工

依据：PRD v1.0 的三轮评审（`ventures/glp1/docs/review-of-prd-v1.0.md`）、2,562 条竞品评论、12 个竞品的界面截图、临床与合规调研。原始材料都在 `ventures/glp1/research/`。

## 0. 一页看完

**做什么**：给说中文的 GLP-1 用户做一个全程伴侣，从第一针陪到停药之后。像发微信一样说一句、拍一张就记完；AI 用中文帮你看懂药效、吃够蛋白、守住肌肉、停药不反弹。

**为什么是这个，而不是 v1.0 的"保肌仪表盘"**

| 我们查到的事实 | 所以 |
|---|---|
| 英文市场的功能已经趋同：按打针日排训练（Preserve）、周期分期（Glapp）、AI 教练（GLPro、MeAgain）、药物水平对照 HRV（JellyPal）都有人做了 | 不靠功能清单取胜 |
| 喊"减脂不减肌"的 3 家，评分人数加起来只有 333 | "保肌"不当招牌 |
| 12 家竞品的界面全是英文，评论里也有人抱怨只有英文 | 中文是目前唯一确实没人占的位置 |
| 我们手上的渠道是 8 万中文粉丝的 X 账号 | 产品要和渠道匹配 |
| 用户最恨三件事：乱扣费、丢数据、AI 识餐不准 | 把"靠谱"做成底线 |
| 用户夸得最多的：一处看全、药物水平曲线、提醒、给医生的报告 | 这些基本功能免费做好 |

**我替你做了 5 个关键决定**（不同意哪条直接说，改起来不贵）

1. **中文优先，面向全球华语用户。** 简体、繁体可切换；药名按地区显示（诺和盈 / 週纖達 / Wegovy）；体重支持公斤、斤、磅。英文只用在给医生的报告里。
2. **先做网页版，不先上 App Store。**
   - 网页版一天能上线，X 里点开就能用，安卓和 iPhone 都能用，不用等审核。医疗类 App 审核慢，还可能被拒；中国区上架还要备案。
   - 代价是提醒不如原生可靠，也读不了 Apple 健康的数据。等数据证明有人用，再套一层原生壳。
   - 如果你坚持第一版就做原生 App，可以走 TestFlight 内测，只是每次改动都要等一两天审核。
   - **安卓不能当次要市场**（2026-11-20 补充，依据 `research/store-reviews/googleplay_brief.md`）：
     - 美国市场里安卓确实小：Shotsy 安卓评分人数约为 iOS 的 38%。
     - 但我们面向中文用户：大陆和东南亚的手机以安卓为主（具体比例待查），而且大陆没有 Google Play，安卓用户分散在华为、小米、OPPO、vivo、应用宝等各家商店。网页版一个链接就能覆盖所有安卓手机，这正是先做网页版的另一个理由。
     - 安卓端的竞争也更松：12 个英文竞品里只有 6 个上了 Google Play，定位最像我们的 Preserve 没有安卓版；MeAgain 在 Play 上最近 200 条评论有一半是 1–3 星，主要是卡顿崩溃和强制年费。
     - 所以 v1 套原生壳时，iOS 和安卓同时做，不能只做 iOS。验收清单第 15 条（各浏览器走一遍主流程）里，安卓要覆盖国产手机自带浏览器。
3. **核心交互是一个"万能输入栏"，不是一堆表单。** 打针、吃饭、体重、不舒服、提问，都在同一个框里说一句或拍一张。这是用中文做 AI 产品最顺手的地方，也是英文竞品的弱项：它们的食物库不认识牛肉面。
4. **"保肌"从招牌降为四个承诺之一。** 四个承诺是：打得明白、吃得够、练得动、停得稳。v1.0 里关于训练和蛋白的设计都保留，只是不再单独拿它拉新。
5. **第一版全部免费，不绑卡。** 用产品里的一个"想要 Pro"按钮和三个小问题来测付费意愿，代替在 X 上发问卷。

**和 v1.0 的主要差别**

| | v1.0 | v2.0 |
|---|---|---|
| 目标用户 | 美国 35–55 岁高收入人群 | 全球说中文的 GLP-1 用户 |
| 招牌 | 保肌 + 血药浓度仪表盘 | 中文、省事、靠谱 |
| 平台 | iOS 原生 | 网页版先行，原生壳后补 |
| 记录方式 | 中央采集键 + 表单 | 万能输入栏（一句话或一张照片） |
| 药物 | 2 种针剂，只认 mg | 按地区的药物目录，含口服药和自定义 |
| 药物曲线 | 纯衰减公式，显示"浓度 78%" | 含吸收过程的模型，只显示相对指数 |
| 安全 | 免责声明 | 危险症状分诊 + 用药安全确认 |
| 停药 | 没有 | 维持期模式 |
| 收费 | $69.99/年，7 天绑卡试用 | 第一版免费；以后不绑卡、不收回免费功能 |

**第一版做哪些**（细节见第 6 节）

- 第 1 天：引导、今天页、万能输入栏、记针和药物水平曲线、副作用记录和危险症状分诊、邮箱登录同步、导出、日历提醒。
- 第 2–3 天：中英双语医生报告、问答、维持期、轻量训练、准确率评测、隐私页面。

**需要你出面的 3 件事**（AI 替不了）

1. 找一位内分泌或减重门诊的医生，或者一位药师，把附录 B、C 和蛋白公式审一遍。一次性的工作，大约几个小时。
2. 新建一个代码仓库，再准备一个域名。
3. 发布时在 X 上发帖，接住最早的 20–30 个内测用户。

## 1. 定位

**一句话**：说中文的人用的 GLP-1 全程伴侣。一句话就能记，AI 用中文讲明白；不卖药、不带货、不给剂量建议，数据归你。

### 1.1 给谁用

| 用户 | 典型情况 | 最需要什么 |
|---|---|---|
| A. 自己在打针的人 | 25–50 岁，多数自费，分布在大陆、港台和海外；信息主要来自小红书、推特和群聊 | 靠谱的中文信息、省事的记录、别忘打针 |
| B. 海外华人 | 看的是说英语的医生，吃的是中餐 | 中餐蛋白估算、中英双语报告 |
| C. 帮父母管的子女 | 父母 55–70 岁，自己不太会用 App | 大字、简单、提醒；子女能看到情况（v1 再做） |

### 1.2 四个承诺

| 承诺 | 用户得到什么 | 对应功能 |
|---|---|---|
| **打得明白** | 知道打了没、下一针何时、现在药效大概在什么水平、不舒服算不算正常 | 记针、提醒、药物水平曲线、副作用记录和应对、医生报告 |
| **吃得够** | 胃口差的时候也能吃够蛋白，吃中餐也能算 | 蛋白目标、中餐速查、一句话和拍照估算 |
| **练得动** | 每周 2–3 次、每次 15–25 分钟，把肌肉留住 | 轻量训练计划、不舒服时自动换轻量版 |
| **停得稳** | 停药以后有人管，反弹能早发现 | 维持期模式、反弹提醒 |

### 1.3 三条底线

这三条直接对应竞品被骂得最多的地方。

1. **不丢数据。** 数据同步到云端，随时能导出，更新不清数据。
2. **不乱收费。** 不绑卡试用，不把已经免费的功能收回去。
3. **不越界。** 不给剂量建议、不诊断、不卖药、不带货；医学内容都标来源。

### 1.4 明确不做

社区、宠物养成、卡路里精细拆解、剂量换算器（units 和 mg 互转、数格子）、任何调整剂量的建议、买药渠道和比价、医生端。

## 2. 核心体验

### 2.1 万能输入栏

常驻在屏幕底部，一个输入框加一个相机按钮。语音不用自己做，用户用手机键盘自带的语音输入就行，中英混说也能识别。

| 用户说或拍 | 识别成 | 界面怎么反应 |
|---|---|---|
| "刚打了 7.5，右大腿" | 用药 | 出确认卡：替尔泊肽 7.5 mg · 右大腿 · 今天 21:30。**用药记录必须点"确认"才入库** |
| "早饭俩鸡蛋一杯豆浆" | 饮食 | 直接记下约 20 g 蛋白，可撤销 |
| 拍一碗牛肉面 | 饮食 | "牛肉面一碗，约 22 g（16–28）"，三个按钮：对 / 少一点 / 多一点 |
| 拍营养成分表 | 饮食 | 读出每 100 g 的蛋白含量，再问"吃了多少" |
| "今早 81.6" | 体重 | 直接记下，可撤销 |
| "有点反酸想吐" | 副作用 | 记下恶心 2 级，同时给出应对卡 |
| "吐了一整天，喝水也吐" | 危险症状 | 不走普通记录，直接出分诊卡（见附录 B） |
| "漏打了两天怎么办" | 提问 | 给出说明书上的写法和来源，并提示"具体请问医生" |
| "我能不能加到 10 mg" | 越界提问 | 不回答，改成帮用户把问题存进"想问医生的问题"，下次自动出现在医生报告里 |

规则：

- **一句话可以包含多件事**，比如"打完针了，体重 82.3，早饭吃了俩蛋"，会拆成三张卡。
- **估算不确定的饮食记录会高亮**，提醒用户调一下份量。
- **最常用的动作不走 AI**：输入栏上方有一排快捷按钮，记一针、称体重、不舒服，以及用户最常吃的 3 样东西。点一下就记完，断网也能用。
- **用户可以拒绝使用 AI**。拒绝后，所有记录仍然可以手动完成。

### 2.2 今天页

打开 3 秒内看到今天该怎么过。

```
┌────────────────────────────────────┐
│ 周三 · 打针后第 2 天 · 加量第 1 周       │
│ 下一针：周一 21:00（还有 5 天 3 小时）   │
├────────────────────────────────────┤
│ 今天这样过                            │
│ 这两天胃口差很常见。先保住 65 g 蛋白，   │
│ 分 4 次吃；训练换成 15 分钟轻量版。      │
│                      [ 我不舒服 ]     │
├────────────────────────────────────┤
│ 蛋白  42 / 65 g（最低线）· 理想 78–97   │
│ ████████░░░░  [+鸡蛋 6] [+豆浆 8] [+蛋白粉 24] │
├────────────────────────────────────┤
│ 药物水平（估算）  ▁▃▆█▇▅▃   指数 86    │
├────────────────────────────────────┤
│ 今天的记录                            │
│ 08:10  两个鸡蛋 + 豆浆        20 g    │
│ 12:30  牛肉面                22 g ±6 │
├────────────────────────────────────┤
│ [记一针] [体重] [不舒服] [+常吃]        │
│ [ 说一句，或者拍一张…            📷 ]  │
└────────────────────────────────────┘
   今天      趋势      问问      我的
```

"今天这样过"这张卡由固定规则生成，文案事先写好并经过审核，不由 AI 临场发挥。规则按下面的顺序匹配，命中第一条就用：

1. 有没处理的危险症状：分诊卡置顶。
2. 今天是打针日：提示剂量和建议部位，附一份打针日清单。
3. 加量后 14 天内：加量周提示（少量多餐、多喝水、训练减量）。
4. 今天是用户的"高症状日"：轻量日建议。
5. 蛋白连续 3 天没到最低线：蛋白日建议。
6. 其他：普通的训练日或休息日。

### 2.3 四个页面

| 页面 | 内容 |
|---|---|
| 今天 | 状态条、今日建议、蛋白进度、药物水平、今天的记录、输入栏 |
| 趋势 | 药物水平曲线、体重趋势、副作用分布、蛋白达标天数、训练次数 |
| 问问 | 和 AI 的问答记录、应对卡和知识卡 |
| 我的 | 药物和排期、提醒、医生报告、备份与导出、单位和语言、反馈 |

### 2.4 上手流程

目标是 90 秒内走完，不用注册就能开始用。

1. **语言和单位**：简体或繁体；公斤、斤或磅。默认跟随手机设置。
2. **所在地区和药物**：按地区显示药名，可以搜索；填剂量、频率、上一次用药时间、当前剂量用了几周。也可以选"还没开始"或"已经停药"。
3. **身高体重**：身高、当前体重；起始体重和目标体重选填。
4. **安全确认**（多选）：肾病或肝病；怀孕、备孕或哺乳；在用胰岛素或磺脲类降糖药；有进食障碍史；未满 18 岁。勾选后，产品会做相应调整，见 4.3。
5. **AI 使用告知**：说明哪些内容会发给 AI、发给谁、不用于训练；可以拒绝。

进入今天页后，记下第一条记录时提示绑定邮箱，理由是"数据只存在这台手机的浏览器里，可能会丢"。

### 2.5 语气和视觉

- **语气**：像一个懂行的朋友。不训人、不扣分、不制造焦虑。
- **视觉**：浅色、暖色调，深色模式跟随系统；首页不超过 4 张卡。头部竞品（MeAgain 的水豚、DreamMe 的鱼）都是温暖的陪伴风格；唯一的黑底硬核风格是 Preserve，目前没有起量。
- **大字模式**：一键切换，给父母辈用。

## 3. 功能规格

### 3.1 打得明白

**药物目录**

- 内容：按地区组织，每个药包含品牌名、通用名、给药途径、频率、常见剂量阶梯、最高剂量、是否画曲线。完整列表见附录 A。
- 用途：品牌名只用于让用户识别自己的药。页面注明商标归各自权利人所有，本产品与药企无关联。

**记一针 / 记一次服药**

- 字段：药物、剂量和单位、时间、部位（左右腹部、左右大腿、左右上臂）、备注。
- 单位：mg 是默认单位。也可以按"格数"、units、mL 记录，但只记录、不换算。
- 校验：剂量超过目录里该药的最高剂量时，要求再确认一次。
- 排期：支持每周一次、每天一次、自定义间隔（比如每 10 天、一周两次）。改了历史记录，曲线和下一针时间跟着重算。
- 部位：建议和上一次不同的部位。
- 漏用：到了时间没记，12 小时后提醒一次"是不是忘了记"。如果用户问漏打怎么办，展示该药说明书上的写法和来源，不替用户做决定。

**提醒**

- 分类：
  - 用户自己设的提醒不限条数，包括用药、补记、买药、称重、蛋白、训练。
  - 系统主动发的提醒每天最多 2 条，22:00 到 8:00 不发。
- 渠道：添加到手机日历（最可靠，所有手机都能用）、网页推送（需要先把网页添加到主屏幕）、邮件。
- 已知限制：网页推送在 iPhone 上要先添加到主屏幕，在没有 Google 服务的安卓手机上基本不可用（待实测）。这是以后做原生版或小程序的主要理由。

**药物水平曲线**

- 永久免费。
- 显示的是"相对指数"：以当前剂量长期使用后的最高点为 100。不显示"体内还剩多少 mg"。
- 模型包含吸收过程，所以最高点出现在打针后一两天，而不是打针那一刻。公式和参数见 5.3。
- 只给参数核实过的药画曲线（司美格鲁肽和替尔泊肽的针剂）。口服药和其他药只显示用药记录和按时率。
- 加量后 14 天标记为"加量周"。临床数据显示，副作用主要集中在加量期。
- 记录满 3 个周期后，根据用户自己的症状打分，找出"个人高症状日"，用于今日建议和训练安排。在此之前，用默认说法"很多人在打针后 1–3 天反应更明显，个体差异很大"。
- 曲线页固定带一个"这是怎么算的"入口，写明：这是按公开的人群平均数据估算的，不是测量值，不能用来调整剂量。

**副作用**

- 快捷记录：恶心、呕吐、反酸打嗝、便秘、腹泻、没胃口、疲劳、头晕、脱发、注射部位反应、情绪、月经变化。每项 0–3 级。
- 每种常见副作用配一张应对卡，结构固定：可以先试试什么、少做什么、什么情况要找医生、来源。目录见附录 C。
- **危险症状分诊**用固定规则判断，不交给 AI。规则见附录 B。触发后，分诊卡置顶并使用警示色，同时暂停当天的训练和饮食提醒。

**医生报告**

- 一页纸，可以选中文、英文或中英对照，用浏览器打印成 PDF。
- 内容：
  1. 用药时间线：药物、每次的剂量和时间、漏用情况、加量节点。
  2. 体重趋势：起点、最低点、当前值、每周变化。
  3. 副作用：类型、次数、出现在打针后第几天。
  4. 饮食和运动：日均蛋白、达到最低线的天数、训练次数。
  5. 想问医生的问题：用户自己加的，加上从越界提问转过来的。
- 页脚注明：数据由用户自行记录，估算值仅供参考。
- 免费，不限次数。

**库存和花费**（第二周做）

剩几次的量、哪天用完、哪天过期、累计花了多少钱。自费用户很在意这个，Glapp 的库存功能在评论里受好评。

### 3.2 吃得够

**蛋白目标**

- 公式：
  - 参考体重：BMI 不到 28 时用实际体重；BMI 达到 28 时用"调整体重" = 理想体重 + 0.4 ×（实际体重 − 理想体重），其中理想体重 = 22 × 身高（米）的平方。
  - 最低线 = 60 g 和 1.0 g × 参考体重，取较大者。
  - 理想区间 = 1.2–1.5 g × 参考体重。
  - 超过 2.0 g × 参考体重时提示"不需要更多了"。
- 例子：身高 160 cm、体重 78 kg，参考体重是 65 kg，最低线 65 g，理想区间 78–97 g。
- 每 4 周或体重变化超过 5% 时重新计算。
- 勾选了肾病或肝病的用户不自动设目标，显示"请向医生确认你的蛋白目标"，用户可以手动填。
- 这套公式综合了几份专家建议，上线前需要营养师或医生确认（见第 9 节）。

**四种记录方式**（按准确度和省事程度排序）

1. **常吃的东西**：点一下就记。初始给鸡蛋、牛奶、豆浆、蛋白粉，之后换成用户自己最常记的 3 样。
2. **说一句**：比如"一碗牛肉面加个蛋"。AI 对照中餐速查表估算，给出数值和范围。
3. **拍营养成分表**：包装食品用这个最准。AI 读出每 100 g 或每份的蛋白含量，用户填吃了多少。不需要条码数据库，哪个国家的包装都能用。
4. **拍一餐**：最不准，放在最后。结果一定带范围，并且让用户确认。

**其他**

- 每餐建议 25–30 g，分 3–4 次吃。
- 晚上的补救提醒：只在距离上一餐超过 3 小时、缺口超过 25 g 时发，每天最多 1 条。推荐体积小、蛋白高的吃法。
- 界面上只突出蛋白。AI 估算时顺带给出热量，放在次要位置，可以关掉。
- 喝水、排便用快捷按钮记录，可选。连续 3 天没排便时给出便秘应对卡。

**准确率验收**

建一个 150 条的中文评测集（100 条文字描述 + 50 张照片，人工标注蛋白克数）。目标是文字类误差的中位数不超过 20%，照片类不超过 35%。每次改提示词或换模型都重跑一遍。这两个数字是初始目标，跑完第一轮再校准。

### 3.3 练得动（轻量版）

- 目标：每周 2–3 次。
- 内容：3 套全身训练（无器械、弹力带、哑铃各一套），每套有标准版（20–25 分钟）和轻量版（10–15 分钟）。动作用文字加简单示意图说明。
- 排法：按周安排，避开高症状日。当天不舒服，点一下换成轻量版或者改天，不算"没完成"。
- 第一版只打勾记录完成情况。记重量和次数、每 4 周一次的力量自测（30 秒坐站、俯卧撑）放到 v1。
- 文案只说"有研究显示，力量训练可以减少大约四分之一的瘦体重流失"，不说"防止肌肉流失"。

### 3.4 停得稳

**用药状态**：加量中 → 维持 → 暂停 → 已停药 → 重新开始。用户可以随时切换，每个状态的今天页不一样。

**停药后的维持期**

- 曲线继续画，显示药物水平逐步下降。按模型估算，最后一针之后，司美格鲁肽大约 32 天、替尔泊肽大约 23 天降到 5% 以下。
- 提示用户每周称 2–3 次体重，取 7 天平均值，和最低点比较：
  - 回升不超过 3%：绿色，正常波动。
  - 回升 3–5%：黄色，提示回看这两周的饮食和运动。
  - 回升超过 5%：橙色，建议和医生聊聊。不给用药建议。
- 蛋白目标和训练计划继续。停药后食欲恢复、也练得动了，这个阶段最适合把肌肉练回来。
- 文案设定合理预期：停药后体重回升很常见，是生理现象，不是失败。
- 重新开始用药时，历史数据全部保留。

以上 3% 和 5% 两个阈值是产品设计上的选择，需要医生确认。

### 3.5 AI 伴侣

AI 在产品里有四个角色，外加一个不由 AI 担任的"安全员"。

| 角色 | 做什么 | 关键限制 |
|---|---|---|
| 记录员 | 把一句话或一张照片变成结构化的记录 | 用药记录必须由用户确认 |
| 讲解员 | 用中文回答问题，依据审核过的知识库和用户自己的数据 | 每个回答带来源；越界的问题不答 |
| 复盘员 | 每周一次总结：哪天反应大、蛋白缺口出在哪一餐、下周一两条建议 | 规律由代码统计，AI 只负责把话说清楚 |
| 翻译员 | 把报告里的备注和问题翻成英文 | 只翻译，不改内容 |
| 安全员（固定规则） | 识别危险症状、校验剂量上限 | 不依赖 AI，规则可测试 |

**讲解员的边界**

| 可以回答 | 不回答，转成"想问医生的问题" |
|---|---|
| 说明书范围内的用药常识（储存、携带、注射步骤、漏用时说明书怎么写） | 要不要加量、减量、停药、换药 |
| 副作用的常见应对方法 | 我适不适合用这个药 |
| 怎么吃够蛋白、怎么练 | 我这个症状是什么病 |
| 解读用户自己的数据 | 哪里买、多少钱、怎么配、格数怎么换算 |
| 出行、时差怎么安排用药时间（按说明书） | 和其他药一起用，对我个人有没有问题 |

知识库来源（文件名和版本上线前核对）：各地区的药品说明书、国家卫健委《肥胖症诊疗指南（2024 年版）》和《成人肥胖食养指南（2024 年版）》、《中国居民膳食指南》、《中国食物成分表》、美国四个学会 2025 年的 GLP-1 营养联合建议、欧洲肥胖研究学会 2026 年共识。

## 4. 信任与合规

### 4.1 数据

- **先用后登**：不注册就能用，数据先存在本机浏览器里。
- **尽早绑定邮箱**：记下第一条记录时就提示。理由要讲清楚：iPhone 的浏览器对 7 天没打开的网站可能清掉本地数据（待实测），而周针用户恰好一周才来一次；另外，X、微信的内置浏览器和 Safari 的数据互不相通。
- **云端同步**：绑定后自动同步，换手机登录即恢复。传输和存储都加密。端到端加密放到 v1 评估。
- **随时导出**：一键导出全部记录（CSV 和 JSON），免费。
- **随时删除**：一键删除账号和全部数据。
- **工程红线：更新绝不丢数据**。每次改数据结构，都要用上一版的真实数据量跑一遍升级测试；升级失败时保留旧数据、不清空；登录或付费状态异常时，绝不隐藏或清空已有记录。Shotsy 2026 年 10 月那次更新后，有用户反映"一年的数据全没了，给医生看的也没了"，这是竞品口碑最大的伤口，不能继承。
- **餐食照片不存服务器**：识别完即丢弃。

### 4.2 隐私和 AI 告知

- 不放广告，不接任何广告或归因 SDK，不出售或共享数据。
- 统计只记"发生了什么动作"，不记具体数值和文字（见 5.6）。
- AI 告知页写明：发送什么（你输入的文字或照片，加上当前药物和单位）、发给谁（模型供应商的名字）、不用于训练、服务器不保存照片。供应商的数据保留和训练条款上线前核对，如实写进隐私政策。
- 单独写一份中文的隐私政策和健康数据说明。

### 4.3 医疗边界

- 每个涉及药物和营养建议的页面，底部固定写：内容仅供参考，不构成医疗建议；调整用药或训练前请咨询医生。
- 安全确认的后果：
  - 肾病或肝病：不自动设蛋白目标。
  - 怀孕、备孕或哺乳：关闭减重目标，提示联系医生。
  - 在用胰岛素或磺脲类：开启低血糖分诊规则。
  - 有进食障碍史：关闭减重目标和体重相关提醒，只保留营养和训练。
  - 未满 18 岁：不提供服务。
- 对外宣传不承诺效果。不用"防止掉肌肉""临床验证""血药浓度""调整剂量"这类说法。
- 附录 B、C 和蛋白公式必须经过一位医生或药师审核后才能公开发布。

### 4.4 地区

- 第一版面向全球华语用户，服务器放在境外，不做大陆的支付，也不在大陆平台推广。
- 正式进入大陆市场是另一个项目：需要本地公司主体、备案，药品信息和生成式 AI 服务还各有资质要求，形态大概率是微信小程序。等海外版的数据出来再决定。
- 产品名、域名、页面标题不使用 Ozempic、Wegovy、诺和盈等商标。

## 5. 技术方案（给负责开发的 AI）

### 5.1 架构

```
手机浏览器（网页应用，可添加到主屏幕）
  ├─ 本地数据库（IndexedDB）：所有记录先写本地，断网可用
  ├─ 固定规则：药物曲线、蛋白目标、危险症状分诊、今日建议
  └─ 调用服务端
        ├─ /api/parse   一句话或照片 → 记录
        ├─ /api/ask     问答
        ├─ /api/review  周复盘
        ├─ /api/sync    数据同步
        └─ /api/auth    邮箱登录
服务端（Node，单容器部署）
  ├─ 数据库（SQLite + 每日备份）
  ├─ 模型供应商 API（密钥只在服务端）
  └─ 邮件服务（登录链接、可选的提醒）
```

技术栈沿用红警项目那一套：pnpm 工作区、TypeScript、Vite 做前端、Node 做服务端、Fly.io 部署。界面文字从第一天就走多语言文件（简体、繁体；报告另有英文）。

### 5.2 数据模型

所有记录都带：`id`、`createdAt`、`updatedAt`、`deletedAt`（软删除）、`occurredAt`（UTC）和当时的时区、`source`（快捷按钮 / 文字 / 营养标签 / 照片 / 手动 / 导入）。

| 表 | 关键字段 |
|---|---|
| Profile | 语言、地区、单位、身高、出生年、每天从几点开始算（默认 04:00）、安全确认项、蛋白目标（自动 / 手动 / 关闭） |
| Medication | 目录 ID 或自定义、品牌名、通用名、途径、频率、间隔小时数、默认单位 |
| Course | 药物、状态（加量中 / 维持 / 暂停 / 已停药）、起止时间 |
| DoseEvent | 药物、数量、单位、部位、时间、备注 |
| Schedule | 药物、固定星期和时间或间隔、下一次时间、提醒设置 |
| FoodLog | 原文、蛋白克数、范围下限和上限、热量（可空）、置信度 |
| WeightLog | 公斤数、时间 |
| SymptomLog | 类型、0–3 级、时间、分诊级别（可空） |
| WorkoutLog | 训练套路、标准版或轻量版、完成情况 |
| WaterLog / BowelLog / Note | 可选 |
| InventoryItem | 药物、剩余次数、过期日、花费、币种 |
| DoctorQuestion | 问题文本、是否已问 |
| AiFeedback | 路线、用户是接受、修改还是拒绝（只存本地，用来算准确率） |

"今天"的边界由 Profile 里的起始时刻决定，照顾夜班和晚睡的用户。用药间隔一律按绝对时间计算，换时区只影响显示。

同步规则：每条记录按 `updatedAt` 取最新的一份；删除用软删除同步。

### 5.3 固定算法

**药物水平**

```
C(t) = Σ D_i · ka / (ka − ke) · ( e^(−ke·Δt_i) − e^(−ka·Δt_i) )     Δt_i = t − t_i ≥ 0
指数(t) = 100 · C(t) / C_稳态峰值
```

- `ke = ln2 / 半衰期`；`ka` 由达峰时间反推。
- `C_稳态峰值`：按当前剂量和当前间隔模拟连续 20 次用药，取最后一个周期里的最大值。

| 药物 | 半衰期 | 达峰时间 | ke（每小时） | ka（每小时） | 稳态下的最高点 |
|---|---|---|---|---|---|
| 司美格鲁肽针剂 | 168 小时 | 约 48 小时 | 0.00413 | 0.060 | 打针后约 36 小时 |
| 替尔泊肽针剂 | 120 小时 | 约 24 小时 | 0.00578 | 0.138 | 打针后约 20 小时 |

半衰期和达峰时间来自公开的药代数据，上线前对照 FDA 说明书第 12.3 节核实。达峰时间在人群中差异很大（替尔泊肽是 8–72 小时），所以只显示相对指数。

**个人高症状日**

记满 3 个用药周期后，按"打针后第几天"（0–6）分组，算每组的平均症状分。某一天的平均分达到个人整体平均的 1.5 倍、且至少出现过 2 次，就标为高症状日。

**体重趋势**

7 天滑动平均（窗口内至少 3 次称重才计算）。最低点取历史上最低的 7 天平均值。连续 2 周每周下降超过 1.5% 时，提示"减得偏快，注意蛋白，可以和医生聊聊"（阈值待医生确认）。

### 5.4 AI 调用设计

| 路线 | 输入 | 输出 | 模型 / effort |
|---|---|---|---|
| parse | 文字或图片，加上用户当前药物、单位、时间 | 结构化 JSON：事件数组，每个事件带类型、字段、置信度 | `claude-opus-5-5` / low |
| ask | 问题、知识库（走缓存）、最少必要的用户情况 | 回答、来源、是否越界、转成的医生问题 | `claude-opus-5-5` / medium |
| review | 代码算好的一周统计 | 150 字以内的总结、最多 3 条规律、最多 2 条建议 | `claude-opus-5-5` / low |
| translate | 报告里的备注和问题 | 英文文本 | `claude-opus-5-5` / low |

实现要点：

- 用官方 SDK `@anthropic-ai/sdk`，密钥只放服务端。
- parse 用结构化输出（`output_config.format`）拿 JSON。这个模型不支持强制工具调用。
- effort 要显式设置，这个模型的默认值是 medium。
- 每次调用后先检查 `stop_reason`。遇到 `refusal` 时提示用户改用手动录入。默认开启服务端回退（`fallbacks: "default"`，beta 头 `server-side-fallback-2026-07-01`）。
- 系统提示词和知识库放在最前面并加 `cache_control`，用户相关的内容放在最后。系统提示词里不放时间戳之类每次都变的内容。
- 图片在前端压成长边不超过 1024 像素的 JPEG 再上传。
- 危险症状的关键词检查在调用 AI 之前先跑一遍，命中就直接出分诊卡。
- 发给 ask 的用户情况只包括：药物、用药状态、距上次用药几天、最近的症状摘要。不发体重和饮食明细。
- 限流：第一版每人每天 20 次 AI 记录、5 次提问。

**成本粗算**（每个活跃用户每月；token 数是我假设的，上线后按实际用量校准）

| 用途 | 次数 | 全部用 Opus 5.5 | 记录改用 Haiku 5.5 |
|---|---|---|---|
| 文字记录 | 60 | $0.5–1.2 | 约 $0.03 |
| 拍照记录 | 30 | $0.6–0.9 | 约 $0.02 |
| 提问 | 10 | $0.2–0.5 | $0.2–0.5（仍用 Opus） |
| 周复盘 | 4 | 约 $0.1 | 约 $0.1（仍用 Opus） |
| 合计 | | 约 $1.4–2.7 | 约 $0.35–0.65 |

范围的下限假设缓存命中，上限假设没命中；用户少的时候缓存基本命中不了。用哪一档模型由你决定。我的建议是先全部用 Opus 5.5 上线，同时用 3.2 节的评测集比较两个模型在"记录"这条路线上的准确率；如果 Haiku 5.5 够用，就把这条路线换过去。

### 5.5 提醒的实现

- 日历：生成一个带闹钟的重复日程文件（.ics），用户点一下加进系统日历。排期变了，提示重新添加。
- 网页推送：只在用户把网页添加到主屏幕后启用。检测到 X 或微信的内置浏览器时，提示"用系统浏览器打开"。
- 邮件：可选。
- 提醒文案不出现药名和剂量，只写"该记一针了"。

### 5.6 统计埋点

只记事件名和类型，不记数值和文字：完成引导、第一条记录、新增记录（类型和来源）、AI 结果被接受 / 修改 / 拒绝、出现分诊卡（级别）、导出报告、绑定邮箱、设置提醒（渠道）、点击"想要 Pro"、回答小问题（题号和选项）。统计工具自己部署，或者用不带广告追踪的服务。

### 5.7 验收清单

1. 新用户 90 秒内走完引导并记下第一针。
2. 输入"刚打了 7.5，右大腿"，出现正确的确认卡；不点确认就不入库。
3. 剂量超过该药最高剂量时，要求再确认一次。
4. 断网时，快捷按钮和手动录入可用；AI 输入提示"联网后再试"。
5. 附录 B 每一行准备至少 3 种中文说法，全部触发分诊卡。
6. 修改一条历史用药记录，曲线和下一针时间立即重算。
7. 清空浏览器数据后用邮箱登录，数据全部恢复。
8. 导出文件包含全部记录。
9. 医生报告在中文、英文、中英对照三种模式下都能打印成一页 A4。
10. 拒绝 AI 告知后，所有记录功能仍可手动完成。
11. 问"能不能加量"，不给建议，生成一条"想问医生的问题"。
12. 评测集达到 3.2 节的准确率目标。
13. 把"每天起始时刻"设为 04:00，凌晨 1 点记的夜宵算在前一天。
14. 用 365 天的模拟数据测试，今天页 1 秒内可操作。
15. 在 X 内置浏览器、微信内置浏览器、Safari、安卓 Chrome 里各走一遍主流程。

## 6. 版本节奏

原则：**用户的数据攒到哪一步，功能就做到哪一步。** 第一天没人有一周的数据，所以周复盘不用第一天做；没人会在第一周停药，所以维持期可以晚两天。

| 版本 | 时间 | 内容 |
|---|---|---|
| v0 第 1 天 | 能发给 20 个人用 | 引导；今天页；万能输入栏（文字和拍照）和快捷按钮；记针和药物水平曲线；副作用记录、4 张应对卡（恶心、便秘、没胃口、疲劳）、危险症状分诊；**维持期轻量版（用药状态切换、停药后今天页、体重回升分级）**；邮箱登录同步、导出；日历提醒；反馈入口 |
| v0 第 2–3 天 | 能公开发布 | 中英双语医生报告；问答和知识库；轻量训练；评测集和提示词调优；隐私政策和条款页；其余应对卡 |
| v0.5 第 1–2 周 | 用户有了一周数据 | 周复盘；可分享的周报卡片（可以隐藏体重绝对值）；库存和花费；繁体中文校对；邮件提醒；可以试 Telegram 机器人做提醒和一句话记录 |
| v1 第 3–6 周 | 数据证明有人用 | 原生壳，iOS 和安卓同时做（读取 Apple 健康 / Health Connect 数据、小组件、可靠推送）；训练记重量和力量自测；家人协助；Pro 和收费 |

代码一天能写完。会占用日历时间的是另外三件事：医生或药师审核内容、评测集标注、隐私和条款页面。这三件可以和开发同时进行。

## 7. 发布和验证：把调查做进产品里

你说得对，在 X 上直接发问卷没人填。所以不发问卷，发产品：先给东西，再看用户的行为。

**发布方式**

1. 内测：发一条"我让 AI 读了 2,562 条 GLP-1 App 的差评，然后做了个中文版"的帖子，附链接。回复或私信的人就是第一批用户，目标 20–30 人。
2. 一周后发一条复盘，讲数据和改动，带出公开版。
3. 之后每周一条开发记录。你的粉丝如果是冲着 AI 和技术来的，这类内容他们本来就爱看；真正用产品的可能是他们自己，也可能是他们的家人。

**产品里的三个小问题**（每次只问一个，点一下就答完）

- 第 3 天："现在最头疼的是什么？"选项：副作用、吃不够、怕掉肌肉、怕反弹、和医生沟通、费用。
- 第 7 天："最想加的功能是什么？"选项加一个自由填写。
- 第 14 天："如果收费，每年多少钱你会付？"再加一句"愿意聊 15 分钟吗"，可以留联系方式。

**看哪些数**

| 指标 | 说明 |
|---|---|
| 激活 | 走完引导后 24 小时内记下第一针或第一餐 |
| 连续 4 周记针的人数 | 最硬的信号：这个人真的在用它管理用药 |
| 第 7 天、第 28 天留存 | |
| AI 结果被直接接受的比例 | 代表识别准不准 |
| 邮箱绑定率、提醒设置率、报告导出数 | 代表信任和依赖程度 |
| "想要 Pro"的点击率 | 付费意愿 |

**第 4 周的决策线**（建议值，可以按实际情况调）

- 加码（做原生壳、开始收费）：激活用户达到 300 人，其中连续 4 周记针的达到 50 人，第 7 天留存达到 25%，"想要 Pro"点击率达到 8%。
- 调整：激活的人多但留不住。按三个小问题的回答重排功能。
- 停：激活不到 100 人，访谈里也没人把它当必需品。

## 8. 收费（第一版不收）

**原则**：不绑卡试用；免费的功能永远免费；价格写清楚。

**试用和取消必须一眼看懂**（计费类评论 273 条，84% 是 1–3 星，是竞品最大的差评来源）：
- 付费页写清楚：试用几天、哪天到期、到期扣多少钱、怎么取消，并配上日期。
- 试用到期前在 App 内提醒一次，附"一键去取消"的入口。
- 始终保留"先用免费版"的按钮，不在填完引导之后才亮出付费墙。
- 涨价或调整只对新用户生效，已经免费的功能不收回。

**以后的设想**

| | 免费 | Pro |
|---|---|---|
| 记针、提醒、药物水平曲线、副作用和分诊 | ✓ | ✓ |
| 手动记录、常吃按钮、导出、医生报告 | ✓ | ✓ |
| AI 记录和提问 | 每天有限额 | 不限 |
| 周复盘、维持期完整计划、训练进阶、家人协助 | — | ✓ |

价格和模型选择是绑在一起的：

- "记录"这条路线如果能用 Haiku 5.5，每个用户每月的 AI 成本大约 $0.5，定价可以做到每年 $19.99–29.99，明显低于 Shotsy 的 $39.99–59.99。这符合你最初的想法：以前要靠人工做的事，现在用 AI 做，价格可以便宜。
- 如果必须全程用 Opus 5.5，每个用户每月成本 $1.4–2.7，就需要更高的价格或更严格的限额。

所以先跑评测，再定价。

## 附录 B：危险症状分诊（固定规则，需医生或药师审核）

分诊卡的统一说法是"这种情况可能需要尽快看医生"，不做诊断。卡片上显示所在地区的急救电话：大陆 120，香港和澳门 999，台湾 119，美国和加拿大 911，新加坡 995，马来西亚 999。

| 用户的说法（举例） | 级别 | 卡片内容 |
|---|---|---|
| 上腹剧痛、疼到后背、疼得直不起腰，可能伴呕吐 | 立即就医 | 可能和胰腺有关，请马上去急诊；当天的训练和饮食提醒暂停 |
| 右上腹疼、发烧、眼白或皮肤发黄 | 尽快就医 | 可能和胆囊有关 |
| 吐了一整天、喝水也吐、一天没怎么尿、站起来眼前发黑 | 尽快就医 | 有脱水和伤肾的风险；不再推荐"喝点蛋白饮料" |
| 手抖、出冷汗、心慌、发懵，且在用胰岛素或磺脲类 | 立即处理 | 先吃 15 g 糖（比如半杯果汁），15 分钟后不缓解就医，并联系医生 |
| 一只眼突然看不清、视野缺了一块 | 立即就医 | 请马上去眼科或急诊 |
| 嘴唇或喉咙肿、喘不上气、全身起疹子 | 立即就医 | 可能是严重过敏，请拨打急救电话 |
| 脖子摸到肿块、吞咽困难、声音嘶哑一直不好 | 尽快就医 | 请告诉医生你在用这类药 |

| 要做手术、胃镜或肠镜 | 提醒 | 请提前告诉医生和麻醉医生你在用这类药 |
